# "축이 있는가" 와 "축이 걸리는가" 는 다른 질문

> Domynion · 2026-09-04 · [`8f63dd3`](https://github.com/yim2412/domynion/commit/8f63dd3) [`2b205fd`](https://github.com/yim2412/domynion/commit/2b205fd)

## 이전에 한 번 데인 자리

증강 카드 둘이 **갈 곳을 잃은 적**이 있었다. 원본을 이식하면서 지형과 이동 규칙이
통째로 바뀌었는데 카드는 그대로 남아 있었다.

| 옛 카드 | 왜 갈 곳이 없나 |
|---|---|
| 항해술(바다 1칸 건너기) | 원본 배는 물길만 이어지면 **어디든 간다**. 사거리가 아니라 경로 탐색이라 곱할 자리가 없다 |
| 삼림 순찰대(숲 비용 −32%) | 원본 지형은 **평지·구릉·산악 셋뿐**, 숲이 없다 |

갈 곳 없는 축을 남기면 **카드가 조용히 아무 일도 안 하고**, 3장 중 하나가 꽝이 되며
그 사실이 화면 어디에도 안 나온다. 그래서 둘을 갈아끼우고, 재발을 막는 테스트를 뒀다.

```python
def test_every_declared_field_is_read_by_some_formula():
    # 모든 축 이름이 augments.py 바깥 소스에 등장하는가
```

## 이번에 던진 다른 질문

*"축이 코드에 있는가"* 말고 **"한 판에 몇 번 걸리는가."**

계수를 곱하는 함수를 감싸 세었다.

| 축 | 발동 횟수 | 카드 |
|---|---|---|
| `expand_speed_pct` | 497,947 | 강행군 |
| `cost_vs_player_pct` · `defense_pct` · `defender_loss_pct` | 342,374 | 정예 · 방벽 · 초토화 |
| `cost_highland_pct` | 325,415 | 산악병 |
| `cost_vs_neutral_pct` | 155,573 | 개척단 |
| `troops_growth_pct` | 104,785 | 징집령 |
| `troops_cap_pct` | 8,519 | 비옥한 땅 |
| `trade_gold_pct` | 213 | 교역로 |
| **`boat_loss_pct`** | **9** | **상륙전** |

**상륙전은 한 판에 9번 걸린다.** 정예 병단의 **1/38,000** 이다.

그 축은 *"배가 도착했는데 목적지가 이미 내 땅"* 일 때만 걸리고, 걸려 봐야 퇴각
벌점 25% 의 30% 를 깎는다.

**막으려던 자리가 그 자리에 다시 생겼다.** 그때는 축이 *없어서* 꽝이었고, 지금은
축이 *거의 안 걸려서* 꽝이다. 그리고 위 테스트는 **초록이다.**

## 약한 테스트에 그 사실을 박았다

지울 테스트는 아니다 — 배선이 통째로 없는 축은 여전히 이쪽이 잡는다.
대신 **못 잡는 것**을 문서에 적었다.

> ⚠ 이 테스트는 "그 축이 판에서 실제로 걸리는가"를 재지 않는다.
> `boat_loss_pct` 는 한 판에 9번 걸렸는데 이 테스트는 초록이다.
> 후자는 판을 돌려야 안다: `python tools/axis_hits.py`

## 재료로 두 번 넘어졌다

**하나 — 감쌀 함수의 시그니처를 잘못 짚었다.** 인자가 둘인데 셋으로 감쌌다.
즉시 `TypeError` 라 금방 알았다.

**둘 — 사람이 없는 판으로 쟀다.** 증강은 사람만 받는데 `human=None` 으로 돌렸다.
그러면 병력 상한 함수가 봇·나라 분기에서 **먼저 return** 해 계수 줄에 도달조차
안 한다. 그 축이 **0회**로 나왔고, 하마터면 *"이 카드가 배선 안 됐다"* 로 읽을 뻔했다.

둘 다 도구 머리말에 박아 뒀다. **다음에 다시 만들면 또 같은 데서 넘어진다.**

## 남은 판단

이 표는 *"그 축이 걸리기는 하는가"* 만 답한다. **횟수만으로 세기를 판정하면 안 된다** —
`trade_gold_pct` 는 213회지만 한 번에 큰 골드가 걸린다.

그래서 결론이 나오는 것은 상륙전 하나뿐이다. **9회는 값이 아무리 커도 판을 못 바꾼다.**
갈아끼울지는 A/B 로 정한다.
