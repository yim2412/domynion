# 안 여는 문서만 썩었다

> Domynion · 2026-09-04 · [`94c99c3`](https://github.com/yim2412/domynion/commit/94c99c3) [`a540edd`](https://github.com/yim2412/domynion/commit/a540edd)

이 프로젝트에는 문서가 둘이다. **대조 문서**(참고 구현과 우리 코드를 나란히 놓은 것,
8,700줄)와 **설계 문서**(우리가 얹는 증강 계층, 460줄).

둘 다 같은 규칙을 지키기로 돼 있었다. 그런데 **한쪽만 썩었다.**

## 발단

증강 UI 를 만들다 설계 문서의 카드 표를 다시 읽었다. 표에 **이미 삭제한 카드 둘**이
그대로 있었다. 이상해서 절마다 코드와 대조했다.

## 설계 문서 — 규칙 절이 한 줄도 안 맞았다

| 문서가 적어 둔 것 | 실제 코드 |
|---|---|
| 상한 = `250 + 영토 × 22` | `2 × (타일^0.6 × 1000 + 50000) + Σ도시레벨 × 250000` |
| 성장 = `max(1.2, 상한 × 0.085 × 여유)` | `(10 + 병력^0.73 / 4) × (1 − 병력/상한)` |
| 지형에 **숲**(방어 1.20) | 숲이 없다. 평지 80 · 구릉 100 · 산악 120 |
| 바다 = "항해술 필요" | 그 카드는 삭제됐다 |
| 시간 종료 **15분** | 170분, 그마저 도달 불가 |

이 문서가 *"구현 작업의 근거로 쓰지 말 것"* 이라는 경고를 **머리말에** 달고 있었다.
그런데 본문은 그대로였다. **머리말만 붙이고 본문을 안 열었다.**

## 더 나쁜 것 — "미해결"이 애초에 다른 문제였다

문서에 **미해결**로 표시된 항목이 있었다.

> 정예 Lv3(−32%) + 산악병 Lv3(−74%) = **−106%**. 두 장만으로 비용이 음수가 된다.
> 현재는 하한 `max(0.2, …)` 가 막고 있다.

실측하니 세 문장이 다 틀렸다.

1. **두 카드는 축이 다르다.** 합산은 같은 축 안에서만 일어나고 할인 카드는 축마다
   하나씩이다 — **−106% 는 일어날 수 없는 계산이었다.**
2. **하한은 막고 있지 않았다.** 하한은 축마다 걸리는데 코드는 **곱**을 쓴다.
   실측 배율 **0.179** 로 하한 아래다.
3. *"두 장으로 최대 할인, 그 뒤론 의미 없다"* 도 반대다. 축이 달라 **계속 곱해지고
   포화가 없다.**

**그런데도 고치지 않았다.** 지켜야 하는 성질은 *"0.2 아래로 안 간다"* 가 아니라
*"0 이하로는 안 간다"* 이고, 양수의 곱은 양수라 공짜 정복은 없다. 고친 것은 문서다.

## 재개 지점이 두 자리에 있었다

설계 문서 마지막 절이 *"다음 세션 재개 지점"* 이었고, **대조 문서에도 같은 절이
있었다.** 두 계획이 경쟁하고 있었다.

설계 문서 쪽이 가리키던 상수 넷이 **하나도 존재하지 않았다.** 1번 항목은
*"충전율 포화를 푼다"* 였는데, 그 규칙은 구현하며 사라져 **문제 자체가 없어졌다.**
문서만 보면 아직 열린 최우선 과제로 읽혔다.

→ 삭제하고 **한 자리만 남겼다.**

## 도구 도움말도 같이 썩어 있었다

```
--clock   안 주면 안전장치가 900초(9,000 tick)에 판을 자른다
```

실제 값은 **10,200초**다. 예전에 상수를 고치면서 **도구 문구를 안 따라 고쳤고**,
그 뒤로 계속 화면에 틀린 안내를 찍고 있었다.

> **주석은 `grep` 으로 찾지만 `--help` 문자열은 눈에 안 띈다.**
> 상수를 고칠 때 옛 값을 `tools/` 까지 훑는다.

## 대조 문서는 — 불일치 0

같은 잣대로 대조 문서도 쟀다. 전투 공식 상수 25개 + 병력·골드·외교 12개.

```
§1 문서 ↔ 상수 불일치: 없다  (37개 대조)
```

낡은 것은 *"되돌려야 한다"* 두 항목의 **완료 표시가 안 달린 것**뿐이었다.
둘 다 오래전에 끝났는데 ✅ 가 없어 아직 할 일로 읽혔다.

## 이 건에서 남긴 규칙

두 문서에 같은 규칙이 걸려 있었는데 한쪽만 썩었다. 차이는 규칙이 아니었다.

> **문서를 지키는 것은 규칙이 아니라 다시 읽는 빈도다.**
> 대조 문서는 세션마다 절을 붙이며 계속 읽었고, 설계 문서는 방향이 바뀔 때
> 머리말만 붙이고 본문을 안 열었다.

그래서 규칙 대신 **구조**를 바꿨다 — 설계 문서의 공식 절을 지우고 *"어디를 보면
되는지"* 만 남겼다. **베껴 적은 수식이 썩은 원인이었다.**
