# 병력을 원본의 10배로 보여주고 있었다

> Domynion · 2026-09-04 · [`34c330d`](https://github.com/yim2412/domynion/commit/34c330d)

## 어떻게 여기까지 왔나

렌더링 폴더는 대부분 WebGL 셰이더라 규칙이 없다고 보고 넘겼던 곳이다. 그런데 파일
하나의 **머리말**이 스스로 이렇게 적어 뒀다.

```
UnitState.health / .missileTimerQueue → CPU progress
```

CPU 에서 값을 계산한다는 뜻이다. 열어 보니 규칙이 셋 들어 있었다. 그래서 **같은
폴더 32개의 머리말만** 다시 훑었고, 그중 하나가 *"number formatting"* 이었다.

## 찾은 것

```ts
export function renderTroops(troops: number): string {
  return renderNumber(troops / 10);      // ← 10으로 나눈다
}
```

**원본은 병력을 표시할 때 10으로 나눈다.** 우리는 날것을 찍고 있었다.
시작 병력 25,000 을 원본은 **`2.5K`** 라고 쓴다.

이 함수는 원본에서 병력이 뜨는 **거의 모든 곳**에 쓰인다 — 병력바, 증가율, 상대
정보, 진행 중인 공격, 소식 로그, 기부 모달, 지도 위 이름 옆 숫자. **한 자리만
고치면 화면 안에서 축이 갈린다.** 열여섯 자리를 한 번에 바꿨다.

⚠ **골드는 나누지 않는다.** 둘을 한 함수로 합치면 골드가 1/10 이 된다.

## 자릿수가 "적당히"가 아니라 표다

| 구간 | 표기 | 예 |
|---|---|---|
| ~999 | 정수 | `999` |
| 1K~10K | 소수 **둘** | `1.23K` |
| 10K~100K | 소수 **하나** | `12.3K` |
| 100K~1M | **정수** | `123K` |
| 1M~10M | 소수 둘 | `1.23M` |

눈금이 일정해야 숫자가 커져도 **폭이 안 흔들린다**(원본이 고정폭 숫자를 쓰는 이유와
같다). 그리고 **내림이 먼저다** — 반올림으로 바꾸면 9,999 가 `10.00K` 가 되어 다음
구간 표기와 섞인다.

## 눈으로 옮기지 않고 원본을 실행해 대조했다

구간 경계에서 틀리기 딱 좋은 표다. 그래서 값을 손으로 적는 대신 **원본 함수를
실제로 돌렸다.**

원본 파일을 통째로 불러오면 클라이언트 트리 전체가 딸려 와 실행되지 않는다.
그래서 **그 두 함수의 본문만 떼어** 실행했다 — 로직은 한 글자도 안 건드린다.

```
대조 54건 · 불일치 0건
```

## 곁가지 — 값 하나가 틀려 있었다

같은 자리에서 시작 병력 표를 대조하다 나왔다.

```python
NATION_START_TROOPS = {..., "hard": 25_000.0, "impossible": 25_000.0}
#                                              ↑ 원본은 31_250
```

원본의 `hard` 줄에 *"Like humans"* 라는 주석이 있어서 거기서 멈춘 것으로 보인다.
**난이도가 넷인데 값이 셋뿐이면 가장 어려운 난이도가 그 아래와 같아진다.**

⚠ **테스트가 넷 중 `easy` 하나만 재고 있었다.**

> 표를 재는 테스트는 **모든 칸**을 재야 한다. 하나만 재면 나머지가 조용히 틀릴 수
> 있고, 실제로 그랬다.

넷을 다 재고 **단조 증가까지** 단언하도록 고쳤다 — 두 난이도가 같아지면 그 난이도는
뜻이 없기 때문이다.

## 남은 것

**값 대조 도구가 지금은 아예 안 돈다.** Node 런타임이 올라가면서 TypeScript 를
그대로 실행하는 방식이 `enum` 을 못 읽게 됐고, 우회 플래그를 줘도 클라이언트 트리
전체를 끌어와 멈춘다.
