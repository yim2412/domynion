# "작다" 고 적어 둔 항목이 넷이었다

> Domynion · 2026-09-04 · [`3efe0c6`](https://github.com/yim2412/domynion/commit/3efe0c6) [`b3630fc`](https://github.com/yim2412/domynion/commit/b3630fc) [`ff4e253`](https://github.com/yim2412/domynion/commit/ff4e253)

## 넘겨 뒀던 폴더

참고 구현의 렌더링 폴더는 26,000줄이다. 대부분 WebGL 셰이더라 **규칙이 없다**고 보고
넘겼다. 그 판단 자체는 맞았다 — 실제로 대부분 그리기 코드다.

그리고 백로그에 이런 항목이 하나 있었다.

> **사일로 재장전 진행바** — 값(`ready_missiles`)은 이미 있다. 그리기만 없다.
> 언제든(작다).

작다고 적어 둔 지 오래됐고, 시간이 남아서 집었다.

## 열어 보니 작지 않았다

참고 구현 파일의 머리말이 이렇게 적혀 있었다.

```
BarPass — instanced health/progress bars and warship veterancy pips.
  1. Health bars (above warships)
  2. Progress bars (below structures — construction + missile readiness)
  3. Veterancy pips (gold rank bars at a warship's bottom-right)

  UnitState.health / .missileTimerQueue / .constructionStartTick → CPU progress
```

**막대 하나가 셋을 보여 준다.** 그리고 마지막 줄 — *"→ CPU progress"* — 은
이 파일이 **셰이더가 아니라 CPU 에서 값을 계산한다**고 스스로 밝힌 것이다.
규칙이 들어 있다는 뜻이다.

### 우리에게 없던 것

| 우선순위 | 무엇 | 우리 상태 |
|---|---|---|
| 1 | **철거 예정**(거꾸로 줄어드는 막대) | **아예 없었다** |
| 2 | 건설 진행 | 아이콘을 **흐리게**만 했다 — 얼마나 남았는지가 없다 |
| 3 | 재장전(사일로 · SAM) | 없었다 — 원래 집으려던 것 |

**철거가 가장 나빴다.** 건물을 철거하면 **30초 동안 계속 돌아가다가** 사라지고,
골드는 한 푼도 안 돌아온다. 그런데 그 30초 동안 화면에 **아무 표시가 없었다** —
눌렀는지조차 알 수 없다. README 에 그 규칙을 적어 두고 있었는데도 화면에는 없었다.

## 하나를 옮기고 멈추지 않았다

같은 파일에 셋이 있었으니, **같은 폴더의 나머지도 머리말만 읽어 보자**고 생각했다.
32개를 훑었다. CPU 계산을 밝혀 둔 것이 넷이었다.

| 패스 | 머리말이 밝힌 것 | 판정 |
|---|---|---|
| `BarPass` | *"→ CPU progress"* | **셋 메움** |
| `NukeTrajectoryPass` | *"arc distances are pre-computed on the CPU"* | 포물선 궤적 — 이미 백로그에 있다 |
| `TerritoryPass` | *"CPU-side tile state and the drip queue"* | 연출(타일이 순차로 물드는 것). 규칙 없다 |
| `TileScatterPass` | *"Per-patch CPU cost is ~12 bytes"* | 성능 메모다 |

그리고 **사거리를 그리는 패스 셋**(SAM 반경 · 사거리 원 · 방어 커버리지)이 전부
같은 기능으로 이어졌다 — **건설 미리보기.** 참고 구현은 677줄이고, **우리에게 통째로
없었다.**

## 677줄을 다 옮기지 않았다

미리보기가 놓기 전에 보여 주는 것 중 **규칙은 하나**다 — 반경.

| 종류 | 반경 | 왜 규칙인가 |
|---|---|---|
| SAM | `150 − 480/(레벨+5)` | **레벨을 탄다.** Lv1 70 · Lv3 90 |
| 방어초소 | 30 | 어디까지 지켜지는가 |
| **공장** | 역 사거리 **110** | ⚠ **이 안에 있어야 철도가 이어진다** |
| 핵 | **바깥** 반경 | 안쪽(전멸)을 그리면 원자탄이 12 대 30 이라 **피해를 2.5배 과소평가**한다 |

공장이 특히 그렇다. 사거리를 모르고 놓으면 **철도가 안 이어지는데 왜 안 이어지는지
알 방법이 없다.** 골드는 이미 나갔다.

그래서 라디얼 메뉴 항목에 `(타일, 반경)` 을 얹고, 커서를 얹은 항목의 원을 지도에
그린다. **업그레이드는 다음 레벨 반경**을 보여 준다 — 지금 레벨을 그리면
*"올리면 얼마나 넓어지나"* 를 알 수 없다.

**안 가져온 것**: 동맹 SAM 사거리 합집합, 관계별 색, 고스트 스프라이트. 셋 다
*"이미 있는 것을 어떻게 보여 주나"* 라 규칙이 아니다. 백로그로 넘겼다.

## 순수 함수 테스트만으로는 "안 그려진다" 를 못 잡는다

계산은 순수 함수로 옮겼고 테스트도 통과했다. 그런데 그리는 쪽이 그 함수를 안 부르면
**테스트는 전부 초록인 채 화면에는 아무것도 안 뜬다.**

그래서 화면을 실제로 그려 **막대 색 픽셀을 셌다.**

```python
before = 막대색_픽셀수()          # 0 이어야 한다
assert before == 0, "막대가 없는데도 그 색이 화면에 있다"
...
assert 막대색_픽셀수() > 0, "배선되지 않았다 — 계산만 맞고 안 그려진다"
```

⚠ **존재가 아니라 개수를 센다.** 처음엔 색이 있는지만 봤더니
*"채우는 폭이 비율을 안 탄다"* 변이가 **살아남았다.** 25% 와 75% 를 그려 픽셀 수를
견주도록 고치고 나서야 잡혔다.

⚠ 그리고 **막 쏜 순간(비율 0)으로 재면 안 된다.** 채울 폭이 0 이라 배경만 그려져
**배선이 멀쩡해도 실패한다.** 한 번 헛짚었다.

## 값으로는 구별할 수 없는 배선이 있었다

SAM 과 사일로의 재장전 시간은 **참고 구현에서 둘 다 90** 이다. 그래서 SAM 이 사일로
상수를 읽어도 **값으로는 티가 안 난다.**

→ 테스트가 하나를 **일부러 다른 값으로 바꿔서** 잰다. 그러지 않으면 상수를 잘못
읽어도 통과한다.

## 이 건에서 남긴 규칙

> **폴더 이름으로 넘긴 곳은 파일 머리말로 한 번 더 훑는다.**
> `BarPass` 는 자기가 CPU 계산이라고 **직접 적어 뒀다.** 예전에 다른 폴더를 그
> 방법으로 훑어 넷을 찾았는데, 이 폴더에는 안 썼다.

그리고 하나 더 —

> **"작다" 고 적어 둔 항목을 믿지 않는다.**
> 그 판단은 *"우리에게 무엇이 없는지"* 를 모르는 상태에서 내린 것이다.
