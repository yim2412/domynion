# Domynion 설계 (v0.1)

실시간 영토 확장 전략 게임. **openfront.io 의 확장 방식**에 **증강 드래프트**를 얹는다.

작성 2026-08-20. 이 문서는 다음 세션의 재개 지점이다.

---

## 1. 왜 이 조합인가

openfront 는 확장의 손맛이 좋지만 **모든 플레이어의 능력이 동일**하다. 그래서 후반이
"누가 더 부지런히 클릭했나"로 수렴하고, 판이 달라도 하는 일이 같다.

증강 드래프트를 얹으면 그 자리에 **빌드**가 생긴다. 정지 때마다 뽑힌 카드 중 하나를
고르고, 같은 카드를 다시 고르면 레벨이 오른다. 빌드를 미리 짜는 것이 아니라
**뽑힌 것들 사이에서 방향을 잡아 가는 것**이다.

정지 자체도 일한다 — 실시간이 끊김 없이 흐르기만 하면 오히려 단조로워진다.
정지가 판을 챕터로 쪼갠다.

---

## 2. 규칙

### 자원은 병력 하나

영토가 병력 상한을 정하고, 병력이 상한에 로지스틱으로 수렴한다.
작은 나라는 빨리 차고 큰 나라는 오래 채운다 — 쌓아 두기만 하는 전략에 천장이 있다.

```
상한   = (250 + 영토 × 22) × 증강계수
성장률 = max(1.2, 상한 × 0.085 × (1 − 현재/상한)) × 증강계수   [초당]
```

### 확장은 연속적이다

타일을 클릭하면 **그 칸이 아니라 그 칸의 소유자 전체**가 대상이 된다.
병력의 일부(슬라이더 비율)를 떼어 국경에 붙이면, 그 부대가 국경을 따라 번지며
타일을 하나씩 사들이고 **병력이 떨어지는 지점에서 저절로 멈춘다.**

```
한 칸 비용 = 2.6 × 지형방어 × (1 + 방어측_충전율 × 2.2) × 방어측_방어계수 × 공격측_비용계수
확장 속도  = min(90, 6 + 부대병력 × 0.055) × 공격측_속도계수    [초당 칸]
```

프론티어를 BFS 큐로 들고 있으므로 확장은 접한 곳에서 바깥으로 자란다.

### 지형

지형이 가진 숫자는 방어 계수 하나다.

| 지형 | 방어 |
|---|---|
| 평야 | 1.00 |
| 숲 | 1.20 |
| 구릉 | 1.45 |
| 산악 | 1.90 |
| 바다 | 통행 불가 (항해술 필요) |

### 승리

정복(마지막 생존) / 지배(육지 80%) / 시간 종료 15분 시 최대 영토.

## 3. 증강

### 원칙

> **증강은 새 규칙을 만들지 않고 기존 수치에 곱해지는 계수다.**

이 원칙이 무너지면 카드 한 장마다 예외 규칙이 하나씩 늘어 판정을 아무도 모르게 된다.

**예외는 항해술 하나.** 계수가 아니라 닿을 수 있는 범위를 바꾼다. 바다를 건널 수단이
아예 없으면 섬이 영원히 죽은 땅으로 남고 후반에 "칠 곳이 없어" 판이 굳는다 —
계수로는 풀 수 없어서 규칙을 하나 늘렸다.

### 드래프트

- 정지: 75초 → 이후 130초마다 = 한 판에 7회
- 매번 무작위 3장 → 하나 선택. 같은 카드를 다시 고르면 레벨 상승 (최대 Lv3)
- 레벨 배율 Lv1/2/3 = 1.0 / 1.7 / 2.3
- 최대 레벨인 카드는 후보에서 제외 (고를 수 없는 카드가 자리를 차지하면 선택지가 실질 2장)

### 카드 (10종)

| 카드 | 축 | Lv1 |
|---|---|---|
| 비옥한 땅 | `troops_cap_pct` | 상한 +18% |
| 징집령 | `troops_growth_pct` | 성장 +22% |
| 정예 병단 | `cost_vs_player_pct` | 적 영토 비용 −14% |
| 개척단 | `cost_vs_neutral_pct` | 중립 비용 −18% |
| 강행군 | `expand_speed_pct` | 확장 속도 +30% |
| 견고한 방벽 | `defense_pct` | 내 영토 방어 +22% |
| 산악병 | `cost_highland_pct` | 구릉·산악 비용 −32% |
| 삼림 순찰대 | `cost_woodland_pct` | 숲 비용 −32% |
| 초토화 | `defender_loss_pct` | 상대 병력 추가 손실 +35% |
| 항해술 | `naval_range` | 바다 1칸 건너기 |

같은 축에 여러 카드가 실리면 **더한다**(곱하지 않는다). 곱하면 카드가 쌓일수록 체감이
급격히 커져 후반이 한 명의 독주가 된다.

### ⚠ 미해결 — 할인 중첩

**정예 Lv3(−32%) + 산악병 Lv3(−74%) = −106%.** 두 장만으로 비용이 음수가 된다.
현재는 하한 `max(0.2, ...)` 가 막고 있지만, 두 장으로 최대 할인에 도달하는 건
설계 결함이다. 그 뒤로는 할인 카드를 더 뽑아도 아무 의미가 없다.

검토할 선택지:
1. 레벨 배율(2.3)을 낮춘다 — 가장 간단하지만 고레벨의 보람이 줄어든다
2. 할인만 곱셈으로 (0.86 × 0.68 = 0.58) — 0 에 수렴하되 넘지 않는다. 축마다 규칙이
   달라지는 게 흠
3. 체감 곡선: 합계 pct 를 `1 − exp(−x)` 류로 눌러 준다

**다음 세션의 첫 작업 후보다.** 지금 고르지 않은 이유는 실측 없이 정하면 또 감이기 때문.

## 4. 파일 구조

```
src/domynion/
  core/            순수 로직 — UI·네트워크 의존 없음
    constants.py   ✅ 밸런스 수치 단일 출처
    gamemap.py     ✅ 대륙 생성(노이즈 높이맵), 타일, 인접, 시작 배치
    augments.py    ✅ 카드 정의, 레벨, 계수 합산(Modifiers), 드래프트
    state.py       ✅ PlayerState + 증강이 반영된 파생 수치
    attack.py      ⬜ 공격 부대, 프론티어 큐, 연속 확장
    engine.py      ⬜ tick(state, dt), 증강 정지, 탈락, 승리 판정
  ai/
    simple_ai.py   ⬜ 언제/누구를/얼마로 치는가 + 증강 선택
    runner.py      ⬜ 실시간 루프에 AI 를 물리는 반응 주기 관리
  ui/
    palette.py     ⬜ 색, 지형 질감
    map_widget.py  ⬜ 지도 + 순위표/시계 오버레이
    hud.py         ⬜ 하단 병력바·공격 슬라이더
    augment_dialog.py ⬜ 증강 선택창
    main_window.py ⬜ 조립, 실시간 타이머
    app.py         ⬜ 진입점 (--shot 스크린샷 모드 포함)
  cli/
    play.py        ⬜ 헤드리스 시뮬레이션 (밸런스 측정용)
tests/             ⬜
```

계층 규칙: `core` 는 아무것도 import 하지 않는다. UI 와 AI 는 `core` 위에 나란히 얹고
서로를 참조하지 않는다.

## 5. 먼저 겪은 함정 (재구현 시 반복하지 말 것)

이 프로젝트는 한 번 갈아엎었다. 아래는 그때 **실제로 당한 것**들이다.

### 그래픽

- **격자선을 지워야 영토가 덩어리로 보인다.** 격자가 있으면 같은 소유자의 인접 타일이
  각각의 칸으로 읽힌다. 소유자가 다른 변에만 굵은 경계선을 그려 그 선이 유일한 선이 되게 한다.
- **노이즈를 타일 안에 가두면 안 된다.** 칸마다 중앙에 밝은 패치가 생겨 격자를 지운
  자리에 체크무늬가 다시 생긴다. 타일보다 큰 주기의 격자에서 값을 뽑아 보간할 것(fBm).
- **지형 문양(나무·산 아이콘)을 또렷하게 그리면 격자가 되살아난다.** 색으로 구분하고,
  실루엣은 산악처럼 색이 헷갈리는 것만 낮은 대비로.
- **타일 사각형을 정수 픽셀에 맞출 것.** 안 맞추면 칸 사이에 반투명 실선이 생긴다.
- **라벨 폰트는 타일 크기가 아니라 영토 덩어리의 실제 폭에 맞춘다.** 타일 비례로 잡으면
  큰 나라 이름이 화면을 덮는다.
- **지형 레이어는 QPixmap 에 구워 둔다.** 서브셀 질감은 타일당 16회 그리기라 매 tick
  다시 그리면 실시간 루프가 눌린다. 실측: 캐시 5.8ms vs 무캐시 90.5ms (**15.6배**).
- **QWidget 서브클래스는 스타일시트 background 를 자동으로 안 칠한다.**
  `WA_StyledBackground` 를 켜야 오버레이 HUD 배경이 나온다.

### 규칙·밸런스

- **방어 비용에 '타일당 병력'(절대값)을 쓰면 판이 교착된다.** 그 값이 상한까지 커져
  비용이 13배로 뛴다. 실측: 40판 중 **29판이 시간 종료**, 1위 점유율이 60초에 41%를
  찍고 600초까지 47%로 정체. 상한 대비 **충전율(0~1)** 로 정규화해서 해결.
- **시작 위치는 전원 같은 대륙에.** 한 명이 섬에서 시작하면 그 판은 시작과 동시에 끝난
  것이나 같다 — 확장할 곳이 없어 병력 상한이 낮게 묶인다. 실제로 3% 에 갇힌 판이 나왔다.
- **지형 임계값은 절대 높이가 아니라 백분위로.** fBm 은 옥타브 평균화로 값이 0.5 근처에
  몰려서 절대 임계값(0.62/0.74)을 아무도 넘지 못한다 — 산악·구릉이 **한 칸도 안 나왔다.**
- **`tile_count` 를 전수 순회하면 안 된다.** 1664칸 × 4명 × 20Hz. 소유가 바뀌는 지점이
  공격 한 곳뿐이므로 증분으로 유지할 것. 이걸 넣고 40판 측정이 9.8초 → 4.2초가 됐다.
- **눈덩이가 빠르다.** 충전율로 고친 뒤 40판 전부 지배 승리, 판 길이 중앙값 73초.
  이번엔 너무 빨라졌다 — 확장 비용/성장률 재조정이 필요하다. 증강이 들어가면 또 달라지므로
  **증강까지 붙인 뒤에 한 번에 재측정**할 것.

## 6. 다음 세션 재개 지점

1. `core/attack.py` — 공격 부대. 프론티어 BFS 큐, `tiles_this_tick` 소수 누적(`_carry`),
   못 먹는 칸은 큐 앞에 되돌려 두기
2. `core/engine.py` — `tick(state, dt)`: 성장 → 공격 진행 → 증강 정지 → 탈락 → 승리.
   영토 수 증분 캐시(`_counts`)를 여기서 유지
3. 증강 정지 흐름: 정지 중에는 시계가 멈춘다. AI 는 즉시 고르고 사람만 기다린다
4. 헤드리스 측정 하네스 → **할인 중첩 문제(3절)를 실측으로 결정**
5. AI → UI 순서

밸런스 측정은 판당 노이즈가 크므로 **최소 40판, 채택 판단은 그 이상**으로 볼 것.
